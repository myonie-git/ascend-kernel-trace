# Simulator collection

## Environment and scope

Start with a trusted, working Ascend application. It may be a direct kernel launcher
or a framework entry point; framework simulation is subject to the installed tool's
support. Do not rebuild a project merely to collect a trace if its existing launcher
works. Kernel binaries, CANN, model libraries, and application dependencies are
provided by the user, not bundled with this skill.

Activate the intended CANN environment yourself or ask the user how it is activated.
`probe_env.py` reads `ASCEND_HOME_PATH` / `ASCEND_TOOLKIT_HOME`, or `--cann-root`, and
queries tool version/help. It does not import `acl`, initialize a device, or inspect
all environment variables. A simulator model directory is only an availability hint.
Probes stay in simulator mode: default/board help can wait for unavailable driver
services in CPU-only environments. Probes are bounded and retain partial version
output on timeout. A failed version query remains marked incomplete even when help
discovery and collection succeed.

v0.1 recognizes these CLI families when local help advertises the required options:

```text
msopprof simulator ...
msprof op simulator ...
```

Only the first family has live simulator validation in this project; the second has
offline command-dispatch coverage. Do not translate that into platform compatibility.

## Prepare a capture

From the skill directory, replace the example values:

```bash
python3 scripts/collect.py \
  --soc TARGET_SOC \
  --kernel-name KERNEL_PREFIX \
  --workdir APPLICATION_DIRECTORY \
  --output NEW_OUTPUT_DIRECTORY \
  --launch-count 1 \
  --timeout-minutes 2 \
  --wall-timeout-seconds 300 \
  --artifact KERNEL_LIBRARY \
  --note 'input shape, dtype, number of cores, and comparison version' \
  -- ./application arg1 arg2
```

The default is planning only. Review the emitted argv, then repeat with `--execute`
before `--`. An explicit `--tool` selects a trusted profiler executable. The script
does not use a shell for the application command. Do not put secrets in argv: the
manifest records it for reproducibility. Hashes cover only the launcher and explicit
`--artifact` files, not every library loaded by an interpreter.

The generated simulator command uses:

```text
--soc-version=TARGET_SOC
--kernel-name=KERNEL_PREFIX
--launch-count=1
--aic-metrics=PipeUtilization,ResourceConflictRatio
--dump=on
--timeout=2
--output=NEW_OUTPUT_DIRECTORY/profile
```

`PipeUtilization` requests compute/transfer instruction events;
`ResourceConflictRatio` requests synchronization detail. The profiler timeout is in
minutes. The separate wall timeout bounds launch, execution and parsing, then signals
only the process group started by this capture. No user process outside that group
is stopped. A timeout may leave useful partial results; it is not a successful full run.

For A/B inspection, use two fresh output directories and separate processes. Keep
the workload/build comparable. Record any smaller input chosen for simulation;
do not substitute its times for the original workload. Smaller core counts are an
optional diagnostic, not a universal requirement.

## Outputs and statuses

Each executed run writes `manifest.json`, `capture.log`, and unmodified profiler
outputs under `profile/`. The manifest records timestamps, command, working directory,
selected environment metadata, hashes and trace inspection summaries.

| Status | Exit | Meaning |
| --- | --- | --- |
| complete | 0 | Successful process, known completion marker, matching target and valid instruction evidence |
| failed | 1 | Launch/tool error; artifacts are retained if created |
| partial | 2 | External interruption or a recognized profiler timeout |
| unverified | 3 | Exit was zero, but target, completion or instruction evidence was insufficient |

These checks concern collection, not output accuracy or agreement with hardware.
v0.1 recognizes the `Start profiling on kernel:` and profiler completion log markers
observed in msopprof 26.1. Different log formats can produce `unverified`; inspect
the logs rather than suppressing the check to claim success.

Look for `OPPROF_*/simulator/core*/trace.json` and `simulator/visualize_data.bin`.
The exact directory suffix is generated by the tool. `inspect_trace.py` avoids
counting combined and per-core copies twice. Import raw data into MindStudio Insight;
the official guide also describes Chrome tracing import. No custom plotting library
is needed for collection or inspection.

Missing `-g` information can remove source-line mapping without removing instruction
PCs. Recompiling changes the artifact under investigation; do so only when needed
and record the new build/hash.
